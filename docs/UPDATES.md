# Автообновление лаунчера

## Как это выглядит для пользователя

1. Лаунчер запускается, показывает главный экран (ничего не тормозит).
2. Через секунду в шапке появляется полоса: **«Доступно обновление v0.2.0»** + первые строки «что нового».
3. Кнопки: **Скачать** → полоса прогресса → **Установить и перезапустить** (или **Страница релиза**).
4. Установка: лаунчер закрывается, файлы заменяются, лаунчер запускается снова уже новой версии.

Ничего не устанавливается само: пользователь всегда нажимает кнопку. Проверку можно выключить
в **Настройки → Поведение → «Проверять обновления лаунчера при запуске»**.

## Как это устроено внутри

| Компонент | Файл | Что делает |
| --- | --- | --- |
| Канал | `src/EHOT.Launcher.Update/UpdateService.cs` | читает релизы через GitHub Releases API, выбирает версию новее текущей |
| Выбор файла | `GitHubUpdateService.SelectAsset` | под ОС и архитектуру: Windows → `.exe`-установщик, macOS → `.dmg`, Linux → `.tar.gz` |
| Скачивание | `DownloadAsync` | потоковая загрузка, прогресс, сверка размера (и SHA-256, если релиз публикует `*.sha256`) |
| Установка | `ApplyAsync` | Windows: `apply-update.cmd` ждёт выхода лаунчера → распаковка → перезапуск. macOS/Linux: честно сообщает, что нужно поставить вручную |
| UI | `ViewModels/UpdateViewModel.cs` + баннер в `Views/MainWindow.axaml` | статус, прогресс, «что нового», кнопки |
| Версия | `Directory.Build.props` → `<Version>` | отображается и сравнивается |

Канал зашивается в сборку через `AssemblyMetadata`:

```xml
<UpdateRepository>owner/repo</UpdateRepository>   <!-- в csproj, по умолчанию Timofei2506/EHOT-Launcher-Releases -->
```

CI подставляет репозиторий релизов сам: `-p:UpdateRepository=${{ env.UPDATE_REPOSITORY }}`
(в `ci.yml` это `Timofei2506/EHOT-Launcher-Releases` — публичный репозиторий только с установщиками).
Если сборка сделана без этого параметра (например, локально из исходников), лаунчер честно
сообщает: «канал обновлений не настроен», а не делает вид, что всё свежее.

## Почему такие решения

- **GitHub Releases** — бесплатно, уже есть в проекте, не нужен свой сервер.
- **Не подменяем файлы у работающего процесса** — на Windows это невозможно, поэтому ожидание выхода.
- **Не «тихое» обновление** — обновление приложения меняет код на диске: это должно быть осознанным действием.
- **Пререлизы включены** (`beta`), потому что проект пока в beta. В релизной ветке достаточно
  переключить `IncludePrerelease = false`.

## Что осталось

- **Подпись**: без неё Windows SmartScreen и macOS Gatekeeper ругаются на новые файлы.
  После подписи имеет смысл проверять подпись перед установкой.
- **Дельта-обновления** (качать только изменённые файлы) — сейчас качается целый архив (~50–70 МБ).
- **macOS**: авто-подмена `.app` запрещена системой для неподписанных бандлов — обновление
  предлагается как `.dmg`, который ставится перетаскиванием.

## Как выпустить новую версию

1. Поднять `<Version>` в `Directory.Build.props` (например, `0.2.0`).
2. `git push` — CI соберёт и прогонит тесты, установщики выйдут артефактами.
3. Опубликовать релиз с тегом `v0.2.0` **в репозитории `EHOT-Launcher-Releases`**
   и приложить к нему три установщика + `SHA256SUMS.txt`.
4. Установленные копии при следующем запуске увидят обновление.
5. Обновить файлы на сайте: положить новые установщики в `site/downloads/`,
   пересчитать `SHA256SUMS.txt` и `manifest.json`, задеплоить (см. `site/README.md`).

Важно: релиз должен быть **опубликован**, а не черновиком — черновики GitHub не отдаёт через API.

## Проверено вживую

Установщики и теги версий вынесены в отдельный **публичный** репозиторий
`Timofei2506/EHOT-Launcher-Releases` (исходный код остаётся в закрытом). API читается
без токена — проверено анонимным запросом:

```
GET https://api.github.com/repos/Timofei2506/EHOT-Launcher-Releases/releases
→ v0.1.0 | draft: false | assets: 4 файла (3 установщика + SHA256SUMS.txt)
```

Именно этот ответ получает лаунчер, поэтому автообновление работает у любого пользователя,
а не только у владельца репозитория. Ветка `-p:UpdateRepository` + `GitHubToken` осталась
как запасной вариант для приватного канала: токен передаётся через `UpdateOptions.GitHubToken`
и хранится в `ISecretStore`.
