# Сайт EHOT Launcher

Статическая страница без сборки и внешних зависимостей (никаких CDN и шрифтов):
`index.html` + `styles.css` + `app.js` + `favicon.svg`. Плюс `robots.txt` и `vercel.json`
(заголовки кэширования и безопасности).

## Что делает `app.js`

Ничего критичного: скачивание работает и без него, потому что ссылки на файлы прописаны
в `index.html` напрямую. Скрипт только украшает и подстраховывает:

* читает `downloads/manifest.json` — версию, размеры и SHA-256 текущей сборки,
  подписывает кнопки («файл · 36.1 МБ») и блок проверки суммы;
* спрашивает публичный репозиторий релизов; если там версия новее, кнопки
  переключаются на её файлы (тоже прямым скачиванием, без редиректа на страницу репозитория);
* если GitHub недоступен — остаётся локальная сборка сайта, без выдуманных версий.

Сайт живой: **https://ehot-launcher-site.vercel.app**

Проект: `ehot-launcher-site` (`prj_tmkDfijS53JE2MrT1nIxkcZrjpVS`), команда
`tgargach12-7359s-projects`, Root Directory: `site`, сборки нет (статика).

Почему пришлось повозиться (чтобы не повторять ошибок):

1. MCP-коннектор Vercel не передаёт `projectSettings` → первый деплой нового проекта
   через него невозможен (`400 missing_project_settings`).
2. Деплой из Git блокируется Vercel: `COMMIT_AUTHOR_REQUIRED` — автор коммита
   должен быть подтверждённым участником команды Vercel.
   Поэтому в репозитории настроен локальный автор
   `git config user.email tgargach12@gmail.com` (без этого деплой блокируется).
3. Каталог `.vercelignore` в корне репозитория оставляет для Vercel только `site/`,
   иначе уезжают все исходники лаунчера.

Обновление сайта после правок:
```bash
cd site
npx vercel@latest deploy --prod --yes --token ВАШ_ТОКЕН --scope tgargach12-7359s-projects
```
(CLI подхватывает настройки связанного проекта из `.vercel/`, он в `.gitignore`.)

## Как сайт отдаёт установщики

Кнопки «Скачать» ведут на файлы **этого же сайта**: `/downloads/EHOT-Launcher-…-setup.exe`,
`/downloads/EHOT-Launcher-…-osx-arm64.dmg`. Редиректов на GitHub нет.
`vercel.json` добавляет к ним `Content-Disposition: attachment` (браузер сразу сохраняет файл)
и кэш на неделю. Работает даже с отключённым JavaScript — ссылки в HTML прописаны.

`downloads/manifest.json` — версия, размеры и SHA-256 текущей сборки; `app.js` читает его
и подписывает кнопки («файл · 36.1 МБ») и блок проверки суммы.
Если в публичном репозитории релизов появится версия новее — сайт переключит кнопки
на её файлы (тоже прямым скачиванием), чтобы не отставать от лаунчера.

**Сами .exe/.dmg в git не коммитятся** (`site/.gitignore`): они лежат в релизе
`EHOT-Launcher-Releases` и на сайте. Обновить файлы на сайте при выпуске новой версии:

```bash
# 1) скачать свежие установщики из своего релиза в site/downloads/
# 2) пересчитать sums и manifest.json
cd site/downloads && sha256sum *.exe *.dmg > SHA256SUMS.txt
# 3) задеплоить (CLI возит содержимое site/ целиком, включая файлы, которые не в git)
cd .. && npx vercel@latest deploy --prod --yes --token ТОКЕН --scope tgargach12-7359s-projects
```
